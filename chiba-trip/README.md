# 千葉旅 行きたいところマップ

LINEで流れていく「ここ行きたい」を1枚に集める地図。
名称・住所・**その日に開いているか（○△✕）**・推奨ルートを載せている。

**→ https://ko-yamatoya.github.io/Projects/chiba-trip/**

## 何が見られるか

- **住所と名称** — Googleマップの短縮URLから店名と住所を復元して表示。住所はタップでコピーできる
- **4つのプラン** — A（全部乗せ）／B（銚子でゆっくり）／C（内房を捨てない）／D（雨ならこれ）。
  チップで切り替えると地図の線も時間割も入れ替わる
- **プラン比較** — 「4案を比較」で、立ち寄り数・走行距離・運転時間・宿到着・帰りの高速・
  落とすものを並べた表になる。各行でいちばん良い数字が緑
- **出発時刻からの時間割** — 出発時刻を選ぶと、各立ち寄り先の到着・出発が計算される。
  営業時間と突き合わせて「間に合わない」「開店まで待つ」を自動で出す
- **営業状況** — 1日目は土曜、2日目は日曜で判定。○（開いてる）／△（要予約・要確認）／✕（休み）
- **豪雨後の状況** — 令和8年8月千葉豪雨（8/13–14）のあと、各所に休業告知が出ていないかを調べた結果

## 場所を足す

Googleマップの共有リンク（`https://maps.app.goo.gl/...`）をそのまま渡す。

```bash
python3 add_spot.py "https://maps.app.goo.gl/xxxxxxxx" --cat 食事 --note "海鮮" --tag ラッキー枠
python3 add_spot.py "千葉県銚子市犬吠埼9576" --name 犬吠埼灯台 --cat 景色
```

短縮URLを展開して店名・住所・`ftid` を取り出し、座標は
国土地理院の住所検索API →（だめなら）OSM Nominatim の順で引く。
千葉県の範囲外の座標が返ってきたら棄却する。同じ `ftid` は上書きなので重複しない。

営業状況（`hours`）と豪雨後の状況（`storm`）は自動では取れないので、
調べて `spots.js` に手で書く。

## プラン・ルートを変える

`route_plan.json` を編集して、

```bash
python3 build_routes.py
```

- `plans[]` … プラン1つ。`tagline` / `good` / `hard` / `who` / `drops` が比較表とカードの文章になる
- `routes[]` … 1日ぶん。`stops` の並びがそのまま回る順番
- `stops[].stay` … 滞在の目安（分）。時間割の計算に効く
- `stops[].gate` … 高速の出入口。`gateways` に登録した地点を指す

OSRM に区間ごとの経路を問い合わせて `routes.js` を作り直す。
一度引いた区間は `.leg_cache.json` に残るので、並べ替えても再問い合わせは差分だけ。
API が落ちていた区間は直線でつなぎ、地図上では破線になる。

## ファイル

| ファイル | 中身 |
|---|---|
| `index.html` | 地図とリスト。ここだけで完結（Leafletは `vendor/` に同梱） |
| `spots.js` | 行きたい場所のデータ（名称・住所・座標・営業状況・豪雨後・電話） |
| `routes.js` | 生成物。4プランのルートの線と距離・所要時間 |
| `route_plan.json` | プランとルートの定義（人が編集するのはこっち） |
| `add_spot.py` | URL／住所 → `spots.js` に1件追加 |
| `build_routes.py` | `route_plan.json` → `routes.js`（OSRMに問い合わせ） |
| `.leg_cache.json` | 生成物。OSRMの区間キャッシュ |

## 断り書き

- 営業情報は **2026-08-23 時点**で公式サイト等を見た内容。直前に変わる。△は電話推奨
- 時刻は「出発時刻＋道路の所要時間＋滞在の目安」の計算値。信号・渋滞・休憩は入っていない
- 高速は令和8年8月千葉豪雨の通行止めが 8/17 1:30 に全解除（千葉東金道路の下り線は車線規制が継続）
- 犬吠埼灯台と屛風ケ浦は、銚子で過ごす案を作るためにこちらで足した提案スポット（「提案」タグ付き）
- 宿は番地を載せていない（公開リポジトリのため）。地図上の点は丁目の代表点
