# 千葉旅 行きたいところマップ

LINEで流れていく「ここ行きたい」を1枚に集める地図。
名称・住所・**その日に開いているか（○△✕）**・推奨ルートを載せている。

**→ https://ko-yamatoya.github.io/Projects/chiba-trip/**

## 何が見られるか

- **住所と名称** — Googleマップの短縮URLから店名と住所を復元して表示。住所はタップでコピーできる
- **当日の営業状況** — 上のタブで土曜／日曜を切り替えると、
  ピンとカードの ○（開いてる）／△（要予約・要確認）／✕（休み）が入れ替わる
- **豪雨後の状況** — 令和8年8月千葉豪雨（8/13–14）のあと、各所に休業告知が出ていないかを調べた結果
- **推奨ルート** — Day1／Day2の線。距離と所要時間は OSRM の実際の道路網から取った実測値
  （時刻は入れていない。出発地と出発時刻が未定のため）

## 場所を足す

Googleマップの共有リンク（`https://maps.app.goo.gl/...`）をそのまま渡す。

```bash
python3 add_spot.py "https://maps.app.goo.gl/xxxxxxxx" --cat 食事 --note "海鮮" --tag ラッキー枠
python3 add_spot.py "千葉県銚子市犬吠埼9576" --name 犬吠埼灯台 --cat 景色
```

短縮URLを展開して店名・住所・`ftid` を取り出し、座標は
国土地理院の住所検索API →（だめなら）OSM Nominatim の順で引く。
千葉県の範囲外の座標が返ってきたら棄却する。同じ `ftid` は上書きなので重複しない。

営業状況（`hours`）と豪雨後の状況（`storm`）は自動では取れないので、
調べて `spots.js` に手で書く。

## ルートを変える

`route_plan.json` の `stops` を並べ替えて、

```bash
python3 build_routes.py
```

OSRM に区間ごとの経路を問い合わせて `routes.js` を作り直す。
API が落ちていた区間は直線でつなぎ、地図上では破線になる。

## ファイル

| ファイル | 中身 |
|---|---|
| `index.html` | 地図とリスト。ここだけで完結（Leafletは `vendor/` に同梱） |
| `spots.js` | 行きたい場所のデータ（名称・住所・座標・営業状況・豪雨後・電話） |
| `routes.js` | 生成物。ルートの線と距離・所要時間 |
| `route_plan.json` | ルートの定義（人が編集するのはこっち） |
| `add_spot.py` | URL／住所 → `spots.js` に1件追加 |
| `build_routes.py` | `route_plan.json` → `routes.js` |
